10-1 類別定義、物件實例化與記憶體配置機制

在程序導向中，變數與函式彼此分立；而物件導向程式設計（OOP）則是透過類別（Class），將實體的特徵資料與操作行為封裝為單一結構。

10-1.1 類別藍圖 vs 堆積記憶體（Heap）物件實例

請把「類別」想像成工程師繪製的規格工程藍圖：藍圖本身不佔用車庫空間。當工廠依據藍圖將汽車真正打造出廠時，這輛停在車庫中、擁有實體引擎與烤漆的車輛，就是物件實例（Instance）。

唯有執行呼叫（如 Car()）時，直譯器才會在堆積記憶體（Heap Memory）中分配一塊獨立的記憶體門牌位址（例如 0x10A8）來容納這個全新物件。

class_blueprint_intro.py 
# 定義 Car 類別規格（遵循 PEP 8 之 PascalCase 命名規範）
class Car:
    pass

# 物件實例化：工廠依照藍圖打造出兩台完全獨立的實體車輛
car_a = Car()
car_b = Car()

# 印出物件與記憶體門牌位址驗證
print(car_a)
print(car_b)
print(f"car_a 記憶體門牌 (ID): {hex(id(car_a))}")
print(f"car_b 記憶體門牌 (ID): {hex(id(car_b))}")
print(f"兩台車是否為完全獨立的個體: {car_a is not car_b}")

10-2 建構函式與實例屬性初始化：__init__() 與 self 參照

每台車出廠時，都需要完成噴漆、掛牌與各項基本設定。Python 透過特殊方法 __init__() 負責物件的組裝初始化。

10-2.1 self 隱性引數傳遞機制

初學者最常產生的困惑在於：「為什麼定義函式時宣告了 def __init__(self, brand, color): 三個參數，後面建立物件 Car("Toyota", "白色") 卻只傳入兩個引數？」

這是因為直譯器在實例化時，會自動完成底層調配：

  1. 直譯器先在 Heap 記憶體為新車開闢專屬停車位（例如位址 0x10A8）。
  2. 隱性傳遞：直譯器會自動把「當前這台新車的記憶體位址」當作第一個引數塞給 self。換言之，self 就是「這台正在被打造的車自己」。
  3. 因此，self.brand = brand 的意義就是：「請把傳進來的品牌，掛在這台新車的行照屬性上」。

10-3 類別屬性與實例屬性：原廠標配與車主改裝

初學者在學到屬性時，最容易搞混「全體共享」與「個人專屬」的差異。我們用最貼近生活的概念來理解：

1. 類別屬性（原廠標配）

工廠藍圖統一規定的出廠規格（例如：所有出廠的車預設都是 4 個輪子）。這是所有車主共同參考的公用規格。

2. 實例屬性（車主個人行照）

買回家後專屬於該台車的資料（例如：車主是誰、目前里程數、烤漆顏色），每台車各自獨立保管。

💡 避坑二大口訣（記住這兩句，觀念永遠不打結！）

口訣一：查問時「先看個人改裝，沒有才看原廠標配」
當你想查這台車有幾顆輪子（car1.wheels），直譯器先看車身有沒有貼改裝標籤；如果車主沒改過，就自然向上看原廠標配是 4 顆。

口訣二：修改時「改誰就是誰，動不到原廠」
如果車主小明爆胎，把自己的車改成了 3 顆輪子（car1.wheels = 3），這只是在車頂貼上一面金屬盾牌。原廠依然是 4 顆，隔壁小華買的車（car2.wheels）依然安安穩穩是 4 顆！

class Car:
    wheels = 4  # 【原廠標配】全體共享

car1 = Car()
car2 = Car()

# 1. 沒改裝前，兩台車都看原廠標配
print(car1.wheels)  # 4
print(car2.wheels)  # 4

# 2. 小明自己改裝，只在 car1 貼上個人標籤
car1.wheels = 3

print(car2.wheels)  # 4 (小華沒改過，依然抬頭看原廠標配)
print(Car.wheels)   # 4 (工廠原廠標配完全沒被動到！)

10-4 方法封裝協定：實例方法、類別方法與靜態方法

在類別內部宣告函式時，依據其第一參數約定與操作範圍，可分為三種標準型式：

方法種類 裝飾器宣告 第一參數 可存取之範圍 典型應用情境
實例方法 (Instance Method) 無（預設） self 可存取自身實例屬性與類別屬性 最常見的物件行為（如車輛加速、帳戶存提款）
類別方法 (Class Method) @classmethod cls 僅能存取類別屬性，無法存取特定個別實例 替代工廠建構函式（如從字串或設定檔解析建物件）
靜態方法 (Static Method) @staticmethod 無強制約束 無法直接存取 self 或 cls 與該類別邏輯相關之獨立工具函式（如輸入格式驗證）

10-6 常見陷阱與新手避坑指南

典型例外或錯誤行為 引發錯誤之典型寫法 直譯器底層原因分析 標準修復指引
TypeError: takes 0 args but 1 given 
class Dog:
    def bark():
        print("汪汪")
d = Dog()
d.bark()
 實例呼叫方法時，直譯器自動傳入 d 的位址給第一參數，但定義時漏寫了 self。 所有實例方法的第一個參數必須顯式寫上 self。
串列作為類別屬性導致全體污染 
class User:
    cart = []  # 類別屬性！
u1 = User()
u1.cart.append("書本")
 所有實例共用同一串列物件，在一個實例新增會導致全體實例一起被影響。 可變物件務必放在 __init__ 內部使用 self.cart = [] 初始化。

10-7 課堂實作驗證題 (Hands-on Practice)

實作題 01：銀行帳戶安全封裝實作（存提款校驗與 @property 防護）

規格需求：
1. 建立 BankAccount 類別，接收 account_id 與初始餘額 initial_balance。
2. 餘額存於 _balance，提供 @property 供安全讀取。
3. 實作 deposit(amount) 與 withdraw(amount)，金額小於等於 0 拋出 ValueError，餘額不足提款印出警告拒絕。

solution_bank_account.py
class BankAccount:
    def __init__(self, account_id, initial_balance=0):
        self.account_id = account_id
        if initial_balance < 0:
            raise ValueError("初始餘額不能為負數")
        self._balance = initial_balance

    @property
    def balance(self):
        return self._balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("存款金額必須大於 0")
        self._balance += amount
        print(f"成功存入 ${amount}，最新餘額為: ${self._balance}")

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("提款金額必須大於 0")
        if amount > self._balance:
            print(f"提款失敗：餘額不足（目前餘額 ${self._balance}）")
            return False
        self._balance -= amount
        print(f"成功提款 ${amount}，剩餘餘額為: ${self._balance}")
        return True

acc = BankAccount("TW888-001", 1000)
acc.deposit(500)
acc.withdraw(1200)
